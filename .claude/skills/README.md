# Skills

**Skills** are packaged knowledge that Claude Code loads **on demand** (only when needed, without weighing on the context when unused). They encapsulate the "how" of a reusable capability that several agents can take advantage of.

## Available skills

- **`design-techniques/`** — formal black-box test design techniques (equivalence classes, boundary values, decision tables, state transitions, pairwise). Used to derive more complete cases when generating manual, BDD or API tests.
- **`e2e-execution/`** — how to run E2E tests in the browser with Playwright MCP (headed/headless mode, locating elements by accessibility, waits to avoid flakiness, evidence). Used by the `e2e-runner` agent.
- **`api-execution/`** — how to run API tests with Newman (the Postman CLI): run a collection, write validations, handle base_url and token, and interpret the results. Used by the `api-runner` agent.
- **`accessibility-testing/`** — how to audit accessibility (a11y) on web (WCAG 2.2, axe-core, keyboard, contrast, ARIA, screen readers), mobile (TalkBack/VoiceOver, accessible labels, touch targets, font scaling) and desktop (UI Automation, controls without an accessible name, keyboard, high contrast), with the WCAG mapping for each platform. Used by the `accessibility-analyst` and referenced by the `mobile-tester` and the `desktop-tester`.
- **`context-research/`** — how to research a story thoroughly before working on it (first the project documentation in `input/documentation/` built by the `project-documenter`; then Jira with comments, subtasks, epic and linked issues; Confluence; Figma; contracts; `input/`) and how to record what is missing as **Missing information** (`MI-XX`) in the context file `output/context/context-US-XXX.md`. Used by the analyst, the strategist, the case generators, the mappers and the `project-documenter`.
- **`testing-guide/`** — interactive assistant that guides the person in choosing what to test and with which agent or skill: it asks step by step, branches based on the answers and recommends or runs; includes the map from platform and test type to the matching agent/skill. Used by the main conversation (subagents cannot ask questions), just like `performance-guide`.
- **`performance-guide/`** — step-by-step guide to plan a performance test with the person (test type, tool, environment, users, ramp-up, duration, think time and thresholds, with suggestions and calculations) and leave the confirmed plan for the `performance-mapper`. Used by the main conversation, because subagents cannot ask the person questions.
- **`project-survey/`** — how to survey an **entire** project via MCP (Jira, Azure DevOps, Confluence, repo, Figma): sweep each tool with bounded queries, sample large backlogs, extract modules, flows, integrations and team, and classify ambiguities, contradictions and gaps into prioritized questions. Used by the `project-researcher`.
- **`salesforce-testing/`** — how to test a Salesforce org: environments and sandboxes, access (profiles, permission sets, OWD, FLS), automation (validations, flows, triggers, order of execution, governor limits, bulk of 200), data (record types, picklists, duplicates), Lightning with Playwright, APIs, Apex tests and releases. Used by the `salesforce-tester`.
- **`token-testing/`** — how to test authentication tokens (JWT, OAuth 2.0/OIDC, session, API keys) and card tokenization (PCI): lifecycle, signature and claims, typical attacks (alg none, replay, scope), secure handling and what not to do with real data. Used by the `wallet-tester`, the `salesforce-tester` and the `web-pentester`.
- **`wallet-testing/`** — how to test digital wallets and payments: balance and ledger (conservation of money), transactions and states, idempotency and retries, double spending and concurrency, rounding and currency, limits, KYC/AML, reconciliation with the gateway and webhooks. Used by the `wallet-tester`.
- **`ecommerce-testing/`** — how to test any online store: catalog, variants, prices and rounding, stock and overselling, cart, checkout, taxes, shipping, coupons, payments in test mode, post-sale, emails, multi-currency, mobile, SEO and legal; which agent covers each part and the typical bugs. Used by the `shopify-tester` and the `wordpress-tester`.
- **`shopify-testing/`** — how to test a Shopify store: development stores, themes and Theme Check, Liquid errors, apps, checkout with Bogus Gateway or test mode, Markets, shipping and locations, discounts, webhooks with HMAC, read-only Admin API and automation with Playwright. Used by the `shopify-tester`.
- **`wordpress-testing/`** — how to test WordPress and WooCommerce: plugins and themes (updates, overridden templates), cache, WP-Cron, REST and Store API, classic or block checkout, gateways in test mode, shipping, taxes, coupons, stock, order statuses, emails, webhooks and roles. Used by the `wordpress-tester`.
- **`prestashop-testing/`** — how to test PrestaShop (1.6, 1.7, 8.x): environments and local smoke with Docker, BO/FO, themes and Smarty templates, modules and overrides, cache and performance (Smarty, CCC, developer mode), checkout (guest, carriers, terms), test payments, combinations and stock, taxes and rounding, multistore, multi-language, emails and the read-only Webservice API. Used by the `prestashop-tester`.
- **`vtex-testing/`** — how to test VTEX: accounts, environments and workspaces (master vs. QA), storefront (Store Framework, FastStore, legacy) and VTEX IO apps, Catalog System and trade policies, pricing, logistics and SLAs, promotions, payments and anti-fraud, the checkout and the orderForm, OMS and marketplace, smoke, regression, performance, security and the read-only APIs. Used by the `vtex-tester`.
- **`sap-testing/`** — how to test SAP (S/4HANA or ECC): SAP GUI (T-codes, Scripting API via COM) and Fiori/UI5 (launchpad, OData), clients and transports, authorizations and roles (PFCG, SU01, SU53, SoD), end-to-end business processes (O2C, P2P, R2R), master data, jobs and IDocs, smoke, regression after a transport, performance (ST03/ST05) and security. Used by the `sap-tester`.
- **`desktop-testing/`** — how to test Windows desktop apps (WinForms, WPF, UWP, Win32, Electron, Java, Qt) and their tooling (Appium + WinAppDriver, pywinauto, Playwright for Electron): control tree and locators, functional (windows, menus, forms, keyboard), installation and updates, files, OS integration (registry, DPI, multi-monitor), smoke, regression, performance, security and accessibility. Used by the `desktop-tester`.
- **`mobile-testing/`** — how to test mobile apps (Android/iOS; native, hybrid or web/PWA): devices and OS matrix, installation/distribution, system permissions, interruptions, connectivity (offline, slow network), deep links and push, lifecycle (background, rotation, kill/relaunch), performance, mobile security (MASVS) and accessibility; automate with Appium. Used by the `mobile-tester` and the `mobile-mapper`.
- **`dependency-analysis/`** — how to analyze dependency security (SCA): ecosystems and lockfiles, CVE/CVSS, direct vs. transitive, reachability, licenses, SBOM, supply chain (dependency confusion, typosquatting) and accepted risk; npm audit, pip-audit, osv-scanner. Used by the `dependency-analyst`.
- **`secure-code/`** — how to do SAST and secret scanning: bug classes (injection, XSS, deserialization, SSRF, crypto…) mapped to OWASP/CWE, semgrep, false-positive triage, secret detection and rotation, and the difference between SAST and DAST. Used by the `secure-code-analyst`.
- **`ai-testing/`** — how to test AI/LLM features (chatbot, RAG, classifier, agent): golden set and evals, hallucinations and grounding/citations, prompt security (direct and indirect injection, jailbreak, PII leakage), output format, robustness, limits, latency/cost, privacy and prompt regression. Used by the `ai-tester`.
- **`async-testing/`** — how to test messaging and events (asynchronous / event-driven): brokers and protocols (Kafka, RabbitMQ/AMQP, SQS/SNS, MQTT, WebSocket, SSE), delivery (at-least-once/exactly-once), ordering by key/partition, idempotency and deduplication, retries and DLQ, schemas and compatibility (Avro/JSON Schema), consumer lag and backpressure, outbox pattern and security. Used by the `messaging-tester`.
- **`graphql-testing/`** — how to test GraphQL APIs: schema and introspection, queries/mutations/subscriptions with variables and fragments, partial errors and nullability (data + errors with HTTP 200), field/type-level authorization, N+1, depth and complexity limits, pagination (cursor/offset) and persisted queries. Used by the `api-runner`, the `api-mapper` and the `api-case-generator`.
- **`soap-testing/`** — how to test SOAP services: WSDL (operations, endpoint, bindings), envelope (Envelope/Header/Body), SOAP 1.1/1.2, validation against the XSD, SOAP Faults, namespaces and SOAPAction, WS-Security (UsernameToken, signature, timestamp), mustUnderstand, types and arrays, idempotency and contract versioning. Used by the `soap-tester`.
- **`grpc-testing/`** — how to test gRPC and real-time APIs: Protocol Buffers (.proto, fields and numbers), the four RPC modes, gRPC status codes, metadata, deadlines and cancellation, TLS/mTLS, Protobuf compatibility and gRPC-Web; WebSocket is covered in `async-testing`. Used by the `api-runner`, the `api-mapper` and the `api-case-generator`.
- **`contract-testing/`** — how to do contract testing: consumer-driven (Pact) and provider-driven contracts, the Pact Broker and can-i-deploy, type matchers and provider states, backward/forward compatibility, and contracts for REST, GraphQL, gRPC and messaging. Used by the `contract-tester`.
- **`seo-testing/`** — how to test SEO and GEO: technical SEO (indexability, robots/sitemap, canonicals, redirects, hreflang), on-page, structured data (JSON-LD, Open Graph), Core Web Vitals, and GEO (AI crawler access, citable content, E-E-A-T, llms.txt). Used by the `seo-analyst`.
- **`data-testing/`** — how to test data and pipelines (ETL): quality dimensions, source↔target reconciliation, schema validation and drift, transformations and SCD, idempotency and incremental loads, late data, PII and lineage. Used by the `data-tester`.
- **`dynamics-testing/`** — how to test Dynamics 365 and other low-code CRM/ERP: environments and solutions, security (roles, business units, column security), Dataverse data model, logic (business rules, flows, plugins, BPF, roll-ups), apps, Web API and end-to-end processes. Used by the `dynamics-tester`.
- **`blockchain-testing/`** — how to test blockchain/Web3 and smart contracts: networks and environments (testnet/local/fork), contract functionality, tokens (ERC-20/721/1155), gas, security (reentrancy, access control, oracles, proxies), signatures (EIP-712) and dApp integration with Hardhat/Foundry. Used by the `blockchain-tester`.
- **`ivr-testing/`** — how to test voice/IVR and voicebots: menu tree (DTMF/ASR), prompts and TTS, flow and error handling, routing and queues, transfers and CTI, telephony (SIP/VoIP, audio, DTMF), recording and compliance (PCI) and voicebots with NLU/LLM. Used by the `ivr-tester`.
- **`game-testing/`** — how to test video games: functional (mechanics, progression, physics, controls), compatibility and performance, saving and persistence, multiplayer and network (anti-cheat), economy/monetization, audio/localization/accessibility and exploratory testing to break the world. Used by the `game-tester`.
- **`pos-testing/`** — how to test point of sale (POS) and hardware: sales flow and cash count, payment methods and pinpad, peripherals (printer, drawer, scale, scanner), fiscal integration, offline mode and synchronization, inventory, roles and cash reconciliation. Used by the `pos-tester`.
- **`observability-testing/`** — how to test observability: structured logs (trace id, no PII), Prometheus/OpenMetrics metrics (RED/USE, cardinality), OpenTelemetry traces (context propagation), healthchecks (liveness/readiness), error tracking, SLIs/SLOs and alerts. Used by the `observability-analyst`.
- **`search-testing/`** — how to test search and relevance (Elasticsearch/OpenSearch, Algolia, Solr, DB full-text): ranking and boosting, typos/fuzzy, synonyms and stemming, facets, zero-results, indexing, security and golden set with metrics (precision@k, nDCG). Used by the `search-tester`.
- **`document-testing/`** — how to test generated documents (PDF/Excel/CSV): data and calculations, unreplaced placeholders, format/locale, structure and layout, metadata, security (password/signature) and PDF accessibility. Used by the `document-tester`.
- **`content-testing/`** — how to review content and typos in the main language: spelling and grammar, visible placeholders and i18n keys, duplicated words, Lorem ipsum, and microcopy consistency (separate from translations, which the `translation-analyst` covers). Used by the `content-reviewer`.
- **`mutation-testing/`** — how to do mutation testing: measure the quality of the test suite with mutants, states (killed/survived/no-coverage), mutation score, survivors vs. equivalents, how to bound the cost (diff/module) and tools per language (Stryker, mutmut, PITest, Infection). Used by the `mutation-analyst`.
- **`k0lmena-automation/`** — conventions for generating automation in k0lmena (`tools/k0lmena`): web/api/mobile structure, names and tags, step reuse, helpers, generic API steps and validation with `npm`, plus the performance templates (k6, Artillery and JMeter). Includes the database verification steps (which are only added when requested). Used by `web-mapper`, `api-mapper`, `mobile-mapper`, `performance-mapper` and `data-verifier`.

## How to add one

Create a folder in `.claude/skills/` with a `SKILL.md` inside:

```
.claude/skills/
└── my-skill/
    ├── SKILL.md          # required: frontmatter (name, description) + instructions
    ├── references/       # optional: details loaded only when needed
    └── scripts/          # optional: scripts the skill runs
```

The `description` in the frontmatter is what Claude Code uses to decide when to load the skill. More detail in [`../../ARCHITECTURE.md`](../../ARCHITECTURE.md).
