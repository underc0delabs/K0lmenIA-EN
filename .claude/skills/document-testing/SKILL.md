# Generated document testing

Many apps generate **PDF/Excel/CSV** files (invoices, reports, account statements) and they are almost never tested: they end up in production with **wrong data, totals that don't add up or unreplaced `{{variable}}`**. Here the document is validated as an artifact. It relies on the `documents` tool and, to obtain the document, on the web/API agents.

## 1. Obtain the document

- Generate it through the real flow (download it from the UI with Playwright, or request it via API with the `api-runner`) with **known test data**, so you can compare against the expected values.
- Save the file in the output folder and run it through `npm run documents` to extract its content.

## 2. Data and calculations

- The document's **data** matches the source (the order, the account, what the UI shows): names, amounts, dates, items.
- The **calculations add up**: subtotals, taxes, discounts and **total**; quantity × price; balances. A one-cent difference is a finding.
- **UI ↔ document consistency**: what the user saw on screen is what comes out in the PDF.

## 3. Placeholders and template

- **No `{{variable}}`, `${var}`, `%s`, Lorem ipsum, TODO** or unreplaced sample text (the tool detects them). It is the most common bug in a generated document.
- Empty optional fields don't leave "undefined", "null" or an odd gap.

## 4. Format, locale and encoding

- **Date, currency and numbers** in the correct format and language (locale); the country's thousands/decimal separators.
- **Accents, Unicode and emojis** display correctly (no "Ã©" or little boxes); the content's language is correct.

## 5. Structure and layout

- Correct **pages**, header/footer on each one, numbering, page breaks where appropriate; **tables that don't get cut off** awkwardly between pages.
- **Multi-page** (a long report) and **multi-sheet** (Excel with several tabs) complete and in order.

## 6. Metadata, security and accessibility

- PDF **metadata** (title, author, date) correct and without leaked internal data.
- **Security**: if it must have a **password** or a **digital signature**, it has one; it doesn't include excess sensitive data.
- **PDF accessibility** (if applicable): tagged PDF, reading order, selectable text (not a scanned image).

## 7. Automate

- `npm run documents` (`tools/documents/documents.py`) extracts the **text and metadata of the PDF** (pypdf) and the **sheets/cells of the Excel file** (openpyxl), and flags **unreplaced placeholders**.
- Compare the extracted text/values against the expected ones (from the source or from an approved reference document); recalculate the totals.
- Test data with "memorable" values (round amounts, unique names) so they are easy to find in the document.

## 8. Typical document bugs

- `{{variable}}` or Lorem ipsum unreplaced in the final document.
- Total that doesn't match the sum of the items, or a miscalculated tax.
- Date/currency in the wrong format; broken accents (encoding).
- Table that gets cut off between pages or overflows; the logo/header is missing.
- The PDF shows different data than the UI.
- PDF that should have a password/signature and doesn't; metadata with internal data.
- Excel with broken formulas or #REF! cells; CSV with the wrong separator.

## 9. Typical questions for the PO (documents)

When it is not written down, they are `MI-XX`:

- Which documents does the app generate and in which format (PDF/Excel/CSV)?
- What is the source of truth for each piece of data and how are the totals calculated?
- Which locale/language and date/currency format?
- Must it have a password, a digital signature, or be an accessible PDF?
- Is there an approved reference document to compare against?
