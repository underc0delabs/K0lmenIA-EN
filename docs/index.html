Introduction

What is k0lmenIA

A team of specialized QA agents for Claude Code, built for manual testing professionals: no programming needed, you work by talking to it inside VS Code.

You provide an input (a user story, a bug observation, an API contract, or simply a Jira key or a Figma link), ask for what you need in natural language, and the right agent produces the result: analyses, plans, test cases in Excel or Gherkin, test data, bug reports, HTML reports, automation and upload to your test management tool. The agents and their deliverables are in English.

◆

1 · Design

Analyze stories, plan, write and review manual, BDD and API test cases (with their estimated time), generate data and charters, and write bug reports.

Saved in output/
▶

2 · Automation

The mapper agents write the automation once; after that it runs with npm, with no tokens.

Saved in tools/k0lmena/
⇄

3 · Management

Test cases, cycles and results with evidence in Xray, QMetry or AIO Tests (test cases also in Azure DevOps), and the closing report.

Your tool + output/

Principles

PrincipleIn practice
Don't make things upIf a step, a piece of data, a rule or a threshold is missing, the agent flags it and asks. Better an artifact with marked gaps than a complete but invented one.
Respect the formatsFields, their order and their values are defined by the templates and scripts, not by the agent.
TraceabilityEverything references the story (US-XXX); every automated scenario carries the test case ID (@TC-001) and the key in the test management tool.
Thoughtful coveragePositive, negative, edge cases and field validations, not just the happy path.
Research before assumingBefore working on a story, the agents review the project documentation (repository, PRs, map of the web app), its comments, subtasks, epic, linked issues, Confluence and Figma. Whatever doesn't show up is marked as Missing information (MI-01).
Token savingsWhat repeats is automated once and then runs without agents.
SecuritySecrets live in the .env at the root, which is never committed; the agents never ask for tokens in the chat.

How to use it

  1. Provide your inputsAsk "Document the project" to gather the context from the repository, the stories and the web app into input/documentation/; put everything else in input/, or pass a Jira key, a Confluence page or a Figma link with the connector active. The agents research the full context and flag what's missing (MI-01).
  2. Ask in natural languageClaude Code picks the agent. You can also name it: "use the web-mapper to…".
  3. Review the resultIn output/ or in tools/k0lmena/.
  4. Automate what repeatsAnd run it with npm test as many times as you want, with no tokens.

Troubleshooting

What happens if the story is missing information?
The agents first look for it in the comments, subtasks, epic, linked issues, Confluence and Figma. Whatever they don't find is recorded as Missing information (MI-01) with the question for the PO, and it's marked in the test cases, the .feature files and every report. It's never filled in with what the app does.
I don't know what I'm missing to install or configure
Run npm run doctor: it checks, section by section, Python, Node, k0lmena, Playwright, Newman, Java, Docker, the fonts, the .env (including that each integration is complete and consistent, without showing secrets), the enabled connectors, git and what the portal, the monitoring and the evals need, and tells you how to fix what's missing. With --section it checks only one part and with --quick it skips the slow checks.
An agent returns "I need you to confirm"
That's on purpose: the agents run as subagents and can't ask you mid-task. Answer the questions and Claude resumes the same agent with your answers.
A new agent doesn't show up
Restart Claude Code: agents are loaded when the session starts.
The web suite fails without a URL or clicks say "outside of the viewport"
No URL: the root .env is missing (cp .env.example .env) or BASEURL/APP_URL is. The viewport issue is already fixed: if VIEWPORT_WIDTH and VIEWPORT_HEIGHT are empty, the window uses 1366x768. If a test fails because a locator changed, ask automation-repairer to fix it.
npm test runs 0 scenarios
You haven't automated anything yet (the folders ship empty) or the TAGS filter doesn't match any scenario.
A scenario never runs
It has the @blocked tag: the mapper couldn't verify a step. The reason is in a comment above the scenario.
"k6 not found"
Run npm run bootstrap:k6 in tools/k0lmena/ or install k6 on the PATH.
"JMeter not found" or "JMeter needs Java"
Run npm run bootstrap:jmeter (or set JMETER_HOME) and install Java 8 or later on the PATH (or set JAVA_HOME).
npm run perf doesn't run a load profile from the agent
That's on purpose: outside an interactive terminal it needs --confirm, which the agent adds only after your confirmation.
An Xray/QMetry/AIO folder shows up as C:/Program Files/Git/…
In Git Bash write the folders without a leading /: "US-001 Signup".
An MCP connector doesn't connect
The variables have to be in the environment where you launch claude (not in the .env). Atlassian and Figma are authorized from /mcp.
Do the tests always check the database?
No. Database checks are added to a .feature only when you ask, and without DB_CONNECTIONS in the .env the suite runs as always.
A Python library is missing
pip install -r requirements.txt
